# Контекст для ИИ-агента

чтобы продолжить разработку и не наступить на грабли, на которые уже наступали.

Что читать:

1. [../CLAUDE.md](../CLAUDE.md) — цель, решения пользователя, состояние, находки. Написан по ходу работы,
   местами хронологически; если расходится с кодом — прав код.
2. Этот файл — грабли и как проверять изменения.
3. [sessions/](sessions/) — сам диалог по дням, если нужно понять «почему так»: какие варианты отбросили,
   что не заработало, какие решения принял человек. Без вывода команд, картинок и «мыслей» агента; личное
   заменено заглушками. История может противоречить коду — она про то, как шли, а не где пришли.

## Карта кода

| Модуль | Что делает | Держать в голове |
|---|---|---|
| `sky.py` | Луна и Солнце (Skyfield + DE421), окна «тело выше min_alt» | время — `Sky.times()`, не `ts.utc(1970, …)`; тело — точка в земных координатах, направление из точки = тело − точка (параллакс) |
| `geo.py` | WGS84 на numpy | высоты над морем считаются высотами над эллипсоидом (геоид сдвигает всё целиком, на направления почти не влияет) |
| `dem.py` | рельеф Copernicus GLO-30/90 по тайлам | PixelIsPoint, `ppd` = узлов на градус, узкие тайлы на высоких широтах; «максимумы блоков» — верхняя граница только внутри тайла |
| `shadow.py` | луч ↔ рельеф (`march`), тень глиссады (`project`) | никогда не шагать по лучу с фиксированным шагом — только `march` |
| `runways.py` | полосы OurAirports, модель захода `Glide` | курс — по координатам концов; смещённый порог; после FAF — горизонтальная площадка до IF |
| `approaches.py` | `approaches.toml` (+ `approaches.local.toml` поверх) | расстояния — от порога; DME от VOR пересчитывать до порога |
| `plan.py` | ночь (линии), разбор точки, поиск окон | сутки — от местного солнечного полудня по долготе, не по часовому поясу |
| `web.py` | сервер и API, `Memo` | тяжёлое — только через `Memo`; параметры — строго проверять |
| `www/index.html` | карта (Leaflet) | каждый асинхронный ответ сверять со снимком параметров `ctxKey()` |
| `www/help.html` | инструкция для фотографа | обновлять вместе с интерфейсом |

## Грабли

Каждая — реальная ошибка из истории проекта (подробности — в CLAUDE.md и sessions/).

**Время и небо**
- `ts.utc(1970, 1, 1, 0, 0, unix)` в Skyfield учитывает високосные секунды, unix-время — нет: 27 с ≈ 400″ для
  Луны, это почти диаметр диска. Только `Sky.times()`.
- Без параллакса Луна смещается до 1° (два диаметра). Направление на тело — всегда из конкретной точки
  наблюдения (`apparent_dir`), с рефракцией.
- Окно «тело выше порога» может быть короче шага выборки, если тело у порога в кульминации: `Sky.windows`
  ищет экстремумы высоты рядом с порогом; в разборе точки каждое окно тела получает хотя бы один отсчёт.

**Рельеф и лучи** (самое коварное место — было переписано дважды)
- Фиксированный шаг по лучу пропускает узкие хребты (шаг 250 м) и вершины между отсчётами (шаг 15 м — у
  острого пика до десятков метров). `march`: грубый шаг ≤ 0,9 блока максимумов (на 89° блок по долготе — 13 м),
  отрезок пропускается, только если **нижний** его конец выше максимумов **обоих** блоков и он не пересекает
  границу тайла; остальное — точно, по клеткам сетки (в клетке рельеф вдоль луча — парабола).
- Точки пересечения с линиями сетки, посчитанные линейной интерполяцией широты, ошибаются на ~1 см — у стыка
  тайлов точка «на линии» попадает в соседний тайл. Нужен шаг Ньютона; концы куска — изнутри куска.
- Наивно обрабатывать всех кандидатов дорого: после первой встречи луча с землёй остальные отрезки уже под землёй.
  Кандидаты — по порядку, порциями 1, 4, 16…
- Отсутствие тайла в GLO-30 ≠ океан: часть стран не выпущена — тогда GLO-90; океан — только если тайла нет в обоих
  списках (tileList.txt). Ошибка сети — `DemError` (503), «как будто море» не запоминать.
- Море — рельеф ровно 0 (так Copernicus заполняет океан); у берега билинейно уже не 0; озёра так не отличить.
- Прямоугольник через ±180° — с «развёрнутыми» долготами (`lon_box`), иначе грузится рельеф полмира.
- Не сделано: в полосе в одну клетку у края тайла рельеф — продолжение последнего ряда, а не интерполяция к соседу.

**Геометрия «где стоять»**
- Камера на 1,7 м (`shadow.EYE_M`) — одинаково в `project()` и в `plan.point()`. В 100 м от самолёта эти 1,7 м —
  около 1°, то есть минуты по времени: без согласования линия на карте и разбор точки расходились.
- Вблизи глиссады соседние точки через 50 м видны в градусах друг от друга — угол считать до отрезков глиссады,
  а не до точек.
- Видимость самолёта и перекрытие тела горами — лучами от самой камеры, без отступов; перекрытие — в каждый
  момент окна, окно — только открытая часть.
- Длительность пролёта — по **относительной** угловой скорости самолёта и тела; скорость на площадке — по
  касательной.
- Фильтры поиска (небо, высота, освещённость) — к каждому моменту **до** склейки в окна.

**Сервер**
- Одинаковые одновременные запросы — один расчёт, общий результат **и общая ошибка** (без повтора); разных
  расчётов в работе и очереди — ограничено, соединений — ограничено. Семафор внутри уже созданного потока
  нагрузку не ограничивает.
- Даты — строго `ГГГГ-ММ-ДД` (strptime принимает `2026-1-1`, а `fromisoformat` дальше — нет) и в пределах DE421
  (до 2053-10-01 с учётом срока поиска). Числа — `isfinite` и пределы.

**Страница**
- Каждый ответ (ночь, точка, поиск, аэропорт) сверять с номером запроса и снимком параметров `ctxKey()`;
  при смене параметров разбор точки сбрасывать (`dropPoint`). Без этого ответ для Луны показывался после
  переключения на Солнце.
- Всё из ответов и справочников в `innerHTML` — через `esc()`.
- CSS-переменные в атрибутах SVG не работают — только через `style=`.
- Схема прицела — на момент окна точки, ползунок — на другую минуту: пользователь принял застывшую Луну схемы за
  луч текущей минуты. Всё, что нарисовано не «на сейчас», подписывать временем и приглушать (`aimStyle`).
- Первое объяснение карты пользователю не зашло («ничего не понимаю»): нужен ответ «когда и где», легенда,
  инструкция. Новые элементы интерфейса — сразу в легенду и в `help.html`.
- Атрибуция OSM — на самой карте (условия тайлов), Copernicus — обе формулировки (WorldDEM-30 и -90).

**Данные и публикация**
- Документы AIP и схемы Navigraph/Jeppesen в репозиторий не кладём; отдельные числа заходов — можно
  (`approaches.toml`, решение пользователя). Платные базы как источник данных не используем.
- Никаких личных данных пользователя: координат, адресов, доменов, сведений о себе. Для примеров — аэропорты и
  центры городов. Личное — в `CLAUDE.local.md` (в .gitignore; агентам-ревьюерам его не читать).
- Перед публикацией — поиск по публикуемым файлам (`git add -A --dry-run`): почта, домены, IP, координаты рядом с
  личными, имя.

## Как проверять изменения

```sh
.venv/bin/python -m unittest discover -s tests -v   # сценарии ревью, рельеф против перебора, сервер
.venv/bin/python tools/check_sky.py                  # быстрый путь против Skyfield: ≤ 0,5″
.venv/bin/python tools/check_shadow.py               # проекция: самолёт ≤ нескольких ″ от центра диска
```

- Новый тест должен **падать** на старом коде: проверять подменой (вернуть старое поведение — тест упал).
  Тесты, проходившие «по случайности», уже были (подставной рельеф с одной высотой на весь мир, наблюдатель
  внутри того же холма, проверка границ пустого списка окон).
- Рельеф — синтетические тайлы `dem.Tile` (`GridDem` в тестах), ожидаемое — перебором, а не тем же кодом.
- Скорость (Mac, LCLK 22): ночь ~1 с, разбор точки ~0,3 с, поиск от точки на 60 дней ~5 с, поиск окон на
  60 дней ~22 с. Заметно медленнее — искать, что считается лишнее.
- Страница — headless Chrome через протокол отладки (node, встроенный WebSocket): `Page.enable` до
  `addScriptToEvaluateOnNewDocument`; выражение, возвращающее промис, `Runtime.evaluate` ждёт — дописывать
  `void 0`; окно уже ~500 px не бывает — телефон смотреть в iframe 375 px. Гонки — подменой `fetch` с ручным
  отпуском ответов.
- Сборка с нуля — клон в пустую папку, Python 3.11, пустой кеш.
- Сервер останавливать `kill $(lsof -ti tcp:8090 -sTCP:LISTEN)`, не `pkill -f` с текстом из своей же команды.

## Работа с пользователем

- По-русски, прямо и коротко. Объяснять общие вещи не нужно.
- Коммит и пуш — только по просьбе.
- На Mac пользователя `grep` — это ripgrep: `rg` или `command grep`. Оболочка — zsh: `$VAR` со списком файлов
  не разбивается на слова — через `xargs`.
- Ревью — Codex: промпт с картой проекта, что проверять по важности, как запускать, формат «файл:строка —
  серьёзность — воспроизведение — исправление»; не читать `CLAUDE.local.md` и `.scrub`. Каждую находку —
  воспроизвести, потом исправлять; «все исправлены» писать только после тестов, падающих на старом коде.

## Как обновить историю

```sh
python3 tools/export_context.py --scrub .scrub
```

Берёт записи сессий Claude Code: папку moonglide и — с начала moonglide — папку nebo, откуда проект вырос
(дальнейшие сессии запускать из папки moonglide). `.scrub` — локальный список замен (в .gitignore). После
выгрузки — проверить поиском: почта, домены, IP, координаты, имя.
